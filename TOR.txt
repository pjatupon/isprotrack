IS ProTrack

ระบบติดตามการจัดซื้อจัดจ้างด้วย AI (AI Procurement Tracking) ของคณะสหวิทยาการ มหาวิทยาลัยขอนแก่น

ประเด็นปัญหา (Pain Point) ทำไมจึงพัฒนาระบบนี้

การจัดซื้อจัดจ้างของภาครัฐอยู่ภายใต้ระเบียบและกฎหมายหลายฉบับ (เช่น พ.ร.บ. การจัดซื้อจัดจ้างฯ พ.ศ. 2560 และระเบียบกระทรวงการคลังฯ พ.ศ. 2560) ซึ่งรายละเอียดซับซ้อนและมีการแก้ไขอยู่เสมอ ส่งผลให้บุคลากรในหน่วยงานพบปัญหาเหล่านี้:

ผู้ขอจัดซื้อไม่ทราบระเบียบและขั้นตอน — ต้องเสียเวลาหาข้อมูล ปรึกษาเจ้าหน้าที่พัสดุซ้ำ ๆ อาจเลือกวิธีจัดซื้อ/เอกสารไม่ถูกต้อง ทำให้คำขอถูกตีกลับไปกลับมา
ใบเสนอราคามีความผิดพลาด — พบตัวเลข/การคำนวณ VAT ที่ไม่ตรงกันบ่อยครั้ง และการระบุยี่ห้อ/รุ่นเฉพาะจนเสี่ยง "ล็อกสเปก" ซึ่งผิดระเบียบ
การร่าง TOR ใช้เวลานานและมีคุณภาพไม่สม่ำเสมอ — ร่างโดยใช้ความรู้เฉพาะบุคคล เนื้อหาไม่ครบถ้วนหรือไม่เป็นไปตามโครงสร้างที่หน่วยงานกำหนด
การกรอกแบบฟอร์มราชการซ้ำซ้อน — ต้องกรอกข้อมูลเดิมหลายครั้งในหลายแบบฟอร์ม ผิดพลาดง่าย
ไม่สามารถติดตามสถานะของคำขอ — ผู้ขอไม่รู้ว่าคำขอของตนอยู่ขั้นตอนใด ตกค้างที่ใคร และเหลือเวลาอีกเท่าไร (ขาดความโปร่งใส/การคาดการณ์ SLA)
คุณลักษณะของระบบ

1. ที่ปรึกษาการจัดซื้อจัดจ้างด้วย AI (AI Consultant)

แชตถาม-ตอบเป็นภาษาไทย อ้างอิงคลังความรู้ระเบียบของหน่วยงาน พร้อมแสดงแหล่งอ้างอิง (Citation) และระดับความมั่นใจ
วิเคราะห์รูปภาพพัสดุ/ครุภัณฑ์ที่แนบมาเพื่อแนะนำประเภท วิธีจัดหา และวงเงินที่เหมาะสม
แนะนำขั้นตอน (Workflow) เอกสารที่ต้องเตรียม และผู้มีอำนาจอนุมัติในแต่ละขั้นตอน
ประเมินระยะเวลาโดยรวม (SLA) ตามประเภทพัสดุและวงเงิน พร้อม Roadmap แต่ละขั้น
ส่งต่อข้อมูลความต้องการจากบทสนทนาไปยังหน้าจัดทำ TOR ได้ทันที
2. การตรวจใบเสนอราคาอัตโนมัติ (Quotation Inspection)

อ่านใบเสนอราคา (ภาพ/PDF) ด้วย AI Vision แล้วสกัดข้อมูลผู้ขาย รายการสินค้า ยอดเงิน ภาษี ออกเป็นโครงสร้าง JSON
ตรวจความถูกต้องทางเลขคณิต (Subtotal / VAT / ยอดรวมสุทธิ) และแจ้งเตือนเมื่อไม่ตรง
ตรวจจับความเสี่ยงการล็อกสเปกจากยี่ห้อ/รุ่น/สเปกเฉพาะที่ปรากฏในเอกสาร
วิเคราะห์ความครบถ้วนของเอกสาร และแนะนำขั้นตอน/workflow ถัดไปตามระเบียบ
3. การร่างและตรวจ TOR ด้วย AI

ร่าง TOR ตามโครงสร้างมาตรฐาน (วัตถุประสงค์ ขอบเขตงาน คุณลักษณะเฉพาะ การส่งมอบ หลักเกณฑ์ตรวจรับ) โดยห้ามระบุยี่ห้อ/รุ่น (ไม่ล็อกสเปก)
ตรวจร่าง TOR อัตโนมัติ ครอบคลุม 4 ประเด็น: ล็อกสเปก / ถ้อยคำกำกวม / ขัดระเบียบ / องค์ประกอบที่ขาด
เก็บประวัติเวอร์ชันของ TOR และส่งออกเป็นไฟล์ Word (.docx) ได้ทันที
4. แบบฟอร์มราชการอัจฉริยะ (Smart Forms)

AI วิเคราะห์แบบฟอร์ม Word ของราชการเพื่อระบุช่องที่ต้องกรอกโดยอัตโนมัติ
เลือกแบบฟอร์มที่ถูกต้องตามประเภทพัสดุ (วัสดุ/ครุภัณฑ์/จ้างเหมา/ซ่อม/เบิก-คืน-เคลื่อนย้าย) และวงเงิน
เติมข้อมูลซ้ำอัตโนมัติจากคำขอ แล้วดาวน์โหลดไฟล์ Word ที่กรอกเรียบร้อยได้ทันที
5. การจัดการคลังความรู้ระเบียบ (Knowledge Base / RAG)

อัปโหลดระเบียบ ประกาศ เอกสารตัวอย่าง (PDF/ภาพ) → AI อ่านข้อความ → ตัดเป็น Chunk → สร้าง Embedding → ค้นหาแบบ Semantic Search
ตรวจสอบไฟล์ด้วย Magic Bytes + SHA-256 checksum ป้องกันไฟล์ปลอมแปลง/ซ้ำ
จัดหมวดหมู่ความรู้ แยกตามหมวด/ข้อ/หน้า และควบคุมการเผยแพร่ตามสิทธิ์ผู้ดูแล/เจ้าหน้าที่
6. การติดตามคำขอและการบริหารจัดการ

แดชบอร์ดภาพรวม + เส้นทางคำขอจัดซื้อแบบ Timeline (ดูสถานะตั้งแต่สร้างคำขอ → ตรวจสอบ → อนุมัติ → เสร็จสิ้น)
บทบาทการทำงานชัดเจน 4 บทบาท (ผู้ขอ / เจ้าหน้าที่ / ผู้อนุมัติ / ผู้ดูแล) พร้อมการบังคับสิทธิ์ RBAC ฝั่งเซิร์ฟเวอร์
บันทึก Audit Log ทุกการกระทำของ AI และผู้ใช้ เพื่อการตรวจสอบย้อนหลัง
หน้าแอดมิน: ตั้งค่า AI (URL/API Key/โมเดล), ปรับแก้ Prompt ได้โดยไม่ต้องแก้โค้ด (พร้อม AI Prompt Assist ช่วยเขียน/ปรับ Prompt), จัดการผู้ใช้/หน่วยงาน/แบบฟอร์ม/หมวดหมู่ความรู้
ประโยชน์ที่ได้รับ

ลดภาระและเวลาของเจ้าหน้าที่พัสดุ — AI ตอบคำถามซ้ำ ๆ ตรวจใบเสนอราคา และร่าง/ตรวจ TOR ฉบับแรกให้แทน เหลือเพียงการตรวจสอบความถูกต้องขั้นสุดท้าย
ผู้ขอจัดซื้อทำงานได้ด้วยตัวเอง — ได้คำแนะนำที่ถูกต้องตามระเบียบพร้อมแหล่งอ้างอิง รู้ขั้นตอน/เอกสาร/ระยะเวลาตั้งแต่แรก ลดการตีกลับซ้ำซ้อน
ลดความเสี่ยงทางกฎหมายและระเบียบ — ตรวจจับการล็อกสเปกและความผิดปกติของเอกสารก่อนเข้าสู่กระบวนการ ทำให้จัดซื้อโปร่งใส ตรวจสอบได้
เอกสารมีคุณภาพสม่ำเสมอ — TOR และแบบฟอร์มได้มาตรฐานตามโครงสร้างที่หน่วยงานกำหนด ไม่ขึ้นกับทักษะเฉพาะบุคคล
เพิ่มความโปร่งใสและคาดการณ์ได้ — ติดตามสถานะคำขอแบบเรียลไทม์ รู้ผู้รับผิดชอบและระยะเวลาที่เหลือ ช่วยวางแผนงบประมาณและการใช้งานได้
คลังความรู้เป็นระบบและยั่งยืน — ระเบียบและแนวปฏิบัติถูกรวบรวมไว้ในที่เดียว อัปเดตง่าย สืบค้นด้วยความหมาย (Semantic Search) ไม่ใช่แค่ค้นคำ
แนวทางการพัฒนาต่อ (Future Work)

ใช้ Embedding แบบ Cloud — เปลี่ยนจาก Local Hash Embedding ไปใช้โมเดล text-embedding-004 (รองรับในโค้ดแล้ว) เพื่อคุณภาพการค้นคืนที่ดีขึ้นสำหรับเอกสารภาษาไทย
เชื่อมต่อระบบราชการกลาง — ผสานกับระบบจัดซื้อจัดจ้างภาครัฐ (e-GP), ระบบสารบรรณอิเล็กทรอนิกส์ และระบบของมหาวิทยาลัย (e-KKU) เพื่อรับ/ส่งเอกสารและสถานะอัตโนมัติ
แดชบอร์ดวิเคราะห์เชิงลึก — สร้างรายงานค่าใช้จ่าย แนวโน้มราคา ความเสี่ยงผู้ขาย และตัวชี้วัด KPI ของกระบวนการจัดซื้อ
แจ้งเตือนอัตโนมัติ — แจ้งเตือนผู้เกี่ยวข้องเมื่อคำขอติดขัด/ใกล้เกิน SLA ผ่านอีเมลหรือ LINE Official
AI เชิงลึกเพิ่มเติม — เปรียบเทียบราคาหลายใบเสนอราคาอัตโนมัติ, สร้างราคากลางเบื้องต้น, สรุปสาระสำคัญของสัญญา และตรวจสอบคุณสมบัติผู้ยื่นเสนอ (คุณสมบัติตามประกาศ)
คัดเลือกผู้ขายและประเมินผล — จัดทำฐานข้อมูลผู้ขาย/ประวัติการส่งมอบ และการให้คะแนนผู้ขายเพื่อประกอบการตัดสินใจ
ขยายผลไปหน่วยงานอื่น — ปรับใช้เป็นต้นแบบสำหรับคณะ/หน่วยงานอื่นในมหาวิทยาลัยขอนแก่น
4. แนวทางและขั้นตอนการพัฒนาผลงาน

เครื่องมือ / โมเดล AI ที่ใช้

Frontend: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4 ร่วมกับ HeroUI v3 (ออกแบบ Mobile-First, ภาษาไทยทั้งหมด)
Backend / Data: Next.js Server Actions + Server Components, Prisma 7 + MariaDB, Better Auth (ยืนยันตัวตน + RBAC ตามบทบาท ผู้ขอ/เจ้าหน้าที่/ผู้อนุมัติ/ผู้ดูแล)
AI Models: ใช้โมเดล Gemini 2.5 Flash Lite (LLM + Vision) ผ่านเกตเวย์ GenAI ของมหาวิทยาลัยขอนแก่น สำหรับงานสนทนาให้คำปรึกษา การอ่านเอกสาร/OCR ภาพใบเสนอราคา การสกัดข้อมูลเป็น JSON การร่างและตรวจ TOR
Embedding (Semantic Search): พัฒนาโมเดล Local Hash Embedding ขนาด 768 มิติ ทำงานแบบออฟไลน์ (คำนวณในระบบ, รองรับภาษาไทยผ่านตัวอักษรและ n-gram) ใช้กับ Pipeline แบบ RAG — รองรับการสลับไปใช้ text-embedding-004 เมื่อมี API
ประมวลผลเอกสาร: MuPDF (แปลง PDF เป็นภาพ), Sharp (ย่อ/บีบอัดภาพก่อนส่งโมเดล), PizZip + Docxtemplater (อ่านและเติมข้อมูลแบบฟอร์ม Word)
การจัดการ Prompt: Prompt ทั้งหมดจัดเก็บในฐานข้อมูลให้ผู้ดูแลปรับแก้ได้โดยไม่ต้องแก้โค้ด พร้อมฟีเจอร์ "Prompt Assist" (AI ช่วยเขียน/ปรับ Prompt อัตโนมัติ)
แนวคิดหลักของการพัฒนา

ออกแบบระบบเป็น สถาปัตยกรรม RAG (Retrieval-Augmented Generation) ที่ผลลัพธ์ AI ทุกอย่างต้องอ้างอิงคลังความรู้ระเบียบของหน่วยงาน พร้อมแนบแหล่งอ้างอิง (Citation) และกำหนดให้ผลลัพธ์ AI เป็นเพียง "ฉบับร่าง" ที่ต้องให้เจ้าหน้าที่ตรวจสอบก่อนบันทึกเป็นทางการ (Human-in-the-Loop) เพื่อลดความเสี่ยง Hallucination

ขั้นตอนการพัฒนา

วิเคราะห์ปัญหาและความต้องการ (Problem Discovery) — ศึกษากระบวนการจัดซื้อจัดจ้างภายในคณะ พบอุปสรรค: ผู้ขอไม่รู้ระเบียบ/ขั้นตอน, ใบเสนอราคาผิดพลาดและล็อกสเปก, การร่าง TOR ใช้เวลานาน, แบบฟอร์มราชการกรอกซ้ำซ้อน และไม่สามารถติดตามสถานะได้
วางสถาปัตยกรรมและเทคโนโลยี — กำหนดโครงสร้างระบบ Web แบบ Full-stack TypeScript, ออกแบบฐานข้อมูล (ผู้ใช้/คำขอ/ใบเสนอราคา/TOR/คลังความรู้/Audit Log) และออกแบบ Pipeline RAG
พัฒนา Pipeline คลังความรู้ (Knowledge Base / RAG) — อัปโหลดระเบียบ/เอกสารตัวอย่าง (PDF, ภาพ) → AI อ่านข้อความแบบละเอียดตามหน้า → ตัดแบ่งข้อความเป็น Chunk ตามหมวด/ข้อ/หน้า → สร้าง Embedding → ค้นหาแบบ Semantic Search ด้วย Cosine Similarity → สร้างบริบทพร้อมแหล่งอ้างอิงให้โมเดลตอบ
พัฒนาโมดูล AI ธุรกิจ —
ที่ปรึกษาการจัดซื้อ (AI Consultant): แชตถาม-ตอบอ้างอิงระเบียบ, รับรูปภาพพัสดุเพื่อวิเคราะห์ประเภทและแนะนำวิธีจัดหา, แสดง Citation และระดับความมั่นใจ, ประเมินระยะเวลา/ขั้นตอน (SLA) และแนะนำวิธีจัดซื้อตามวงเงิน
ตรวจใบเสนอราคา (Quotation Inspection): อ่านใบเสนอราคา → สกัดข้อมูลผู้ขาย/รายการ/ยอดเงินเป็น JSON → ตรวจเลขคณิต (Subtotal/VAT/ยอดรวม) และตรวจจับความเสี่ยงการล็อกสเปกจากยี่ห้อ/รุ่นที่ปรากฏ
ร่าง/ตรวจ TOR: สร้าง TOR ตามโครงสร้างมาตรฐาน (วัตถุประสงค์/ขอบเขต/คุณลักษณะ/การส่งมอบ/เกณฑ์ตรวจรับ) ห้ามระบุยี่ห้อ, ตรวจหาการล็อกสเปก/ถ้อยคำกำกวม/ความไม่ครบถ้วน, บันทึกประวัติเวอร์ชัน, ส่งออกไฟล์ .docx
แบบฟอร์มอัจฉริยะ: AI วิเคราะห์แบบฟอร์ม Word ของราชการ → ระบุช่องที่ต้องกรอก → เลือกฟอร์มตามประเภทพัสดุและวงเงิน → เติมข้อมูลอัตโนมัติและดาวน์โหลดไฟล์ที่กรอกเรียบร้อย
บูรณาการ Workflow และความปลอดภัย — ผูกทุกโมดูลเข้ากับกระบวนการจัดซื้อ (ปรึกษา → ส่งคำขอ → ตรวจใบเสนอราคา → อนุมัติ → ติดตาม), บังคับสิทธิ์ RBAC ฝั่งเซิร์ฟเวอร์ทุกครั้ง, บันทึก Audit Log ทุกการตัดสินใจของ AI และผู้ใช้
ทดสอบและปรับปรุงต่อเนื่อง — เขียน Unit Test (การตัด Chunk, Embedding, ตรวจสอบไฟล์, Pipeline, นโยบายสิทธิ์), ปรับแต่ง Prompt โดยผู้ดูแลผ่านหน้าแอดมินจริง, ตรวจสอบผลลัพธ์ AI กับผู้เชี่ยวชาญพัสดุเป็นวงจรซ้ำ
